# Database migration problems

Check the migration status with:

```bash
docker compose exec seek bundle exec rake db:migrate:status RAILS_ENV=production
```

If all migrations show `up`, everything is fine and no action is required.

If you encounter an entry such as:

```text
down     20260211160844  Fix doorkeeper foreign keys
```

then you need to correct the database manually.

Run:

```bash
docker compose exec seek bash
mysql -u seek -p"<PASSWORD FROM YOUR docker-compose.yml>"
ALTER TABLE seek.users MODIFY COLUMN id BIGINT auto_increment NOT NULL;
exit;
```

If your database is named `seek_docker`, adjust the database name accordingly.

In rare cases, another patch may also be required:

```sql
INSERT INTO schema_migrations (version) VALUES ('20251211150643');
```

After that, you should be able to migrate successfully with:

From inside the SEEK container:

```bash
bundle exec rake db:migrate RAILS_ENV=production
```

From the host machine:

```bash
docker compose exec seek bundle exec rake db:migrate RAILS_ENV=production
```

Or simply let the `update.sh` process handle it.
