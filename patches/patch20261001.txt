# Database migration problems

Test database migration problems with
```
docker compose exec seek bundle exec rake db:migrate:status RAILS_ENV=production
```
If all migration show "up" anything is fine - nothing to do.


If you encounter 
```
down     20260211160844  Fix doorkeeper foreign keys
```
you need to make a correction to the data base manually

```
docker compose exec seek bash
mysql -u seek -p<PASSWORD FROM YOUT docker-compose.en>
ALTER TABLE seek.users MODIFY COLUMN id BIGINT auto_increment NOT NULL;
exit;
```

If your database ist names "seek_docker" change accordingly.

In a rare situation another patch was reported to be necessary:
```
INSERT INTO schema_migrations (version) VALUES ('20251211150643');
```

After that you should be able to migrate succesful with:

from within seek container:
```
bundle exec rake db:migrate RAILS_ENV=production
```
or, from host:
```
docker compose exec seek bundle exec rake db:migrate RAILS_ENV=production
```
or just by update.sh process
